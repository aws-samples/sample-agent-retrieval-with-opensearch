# Threat model

Scope: the OpenSearch Serverless collection, the Amazon Bedrock AgentCore runtime, Amazon OpenSearch Memory, the two
Gateways and the Streamlit app. Method: STRIDE over the data flows in
[architecture.md](architecture.md). This is sample content, deployed in a non-production account. It
holds no customer data: the catalog is built from the public Amazon ESCI shopping-queries dataset and the shoppers
(Alice, Bob) are made up. File and line references are to the commit that carries this document.

A Threat Composer export of the tables below is in [threat-model.tc.json](threat-model.tc.json), generated by
`scripts/threat_model_to_tc.py`; a unit test fails if the two drift apart.

## Assets

| Asset | Why it matters |
|---|---|
| AWS account credentials and IAM roles | Lateral access to other resources in the account |
| Per-shopper memory (Amazon OpenSearch Memory) | Preferences and facts about a shopper; must not leak between shoppers |
| Product catalog (OpenSearch Serverless) | Integrity of what the agent recommends |
| Inventory bearer token and Cognito client secret | Access to the Gateways |
| Model invocations (Bedrock) | Cost and misuse of the model |
| Deployment packages (runtime, Lambda, app tarball) | Code that runs with the roles above |

## Assumptions

- The EC2 instance that hosts the app (the optional `infra/serverless/app-host.yaml`, or your own) has no inbound
  rules in its security group, and the operator keeps it that way (the app is reached through SSM Session Manager only). Row 11 depends on this.
- The account is a non-production sandbox. Anyone with administrator access to it can read every secret and package in
  it; the model does not defend against that.
- Account budget alarms are the operator's to set.

## Trust boundaries and data flows

1. Operator laptop to the app on EC2: SSM Session Manager port forward only. Streamlit listens on 127.0.0.1 of the
   instance (`infra/ec2/install_app.sh`), so nothing listens on a routable address.
2. App to AgentCore runtime: SigV4 `InvokeAgentRuntime` with the app role.
3. Runtime (VPC mode) to the collection: SigV4 for `aoss` with the runtime role, through the private interface
   endpoint (`infra/serverless/agentcore/main.py:68-94`). The collection's network policy admits only that endpoint,
   and its data access policy names the runtime role with read permissions.
   3a. Outside MCP client to the catalog Gateway: the Gateway URL is a public AWS endpoint. The client presents a
   Cognito client-credentials JWT (24 hours at most) with scope `catalog/search`. The Gateway invokes the search Lambda
   with its own role; the Lambda runs in the VPC and reads the collection through the same endpoint. The demo app can
   mint this token because its role may read the Cognito app client (`cognito-idp:DescribeUserPoolClient`,
   `agentcore.yaml:476`).
4. Runtime to the inventory Gateway: the runtime reads the Cognito client id and secret from Secrets Manager
   (`sample-agent-ret/inventory-client`), requests a client-credentials token from the Cognito token endpoint over TLS, and
   sends it as a bearer token (`main.py:97-109`).
5. Runtime and app to Bedrock (models, embeddings, rerank) and to OpenSearch Memory: IAM roles scoped to those APIs (the app role: five `osm:` actions on the one space, and only with an actor named).

## Threats and mitigations

| # | STRIDE | Threat | Mitigation | Residual | Evidence |
|---|---|---|---|---|---|
| 1a | Spoofing | Someone calls the catalog Gateway without credentials | Custom JWT authorizer with one allowed client and one allowed scope; the Lambda has no resource policy and is invoked only by the Gateway role; reserved concurrency of 5 limits abuse | A stolen token works for up to 24 hours; there is no revocation step | `agentcore.yaml:173,229-257,267-271` |
| 1b | Spoofing | Someone calls the inventory Gateway without credentials | Custom JWT authorizer with one allowed client and scope; the Cognito client secret is copied into a secret that only the runtime role can read | The client secret does not expire and is rotated only by replacing the Cognito app client | `inventory-gateway.yaml:44-56,252-257`; `agentcore.yaml:408-416` |
| 2 | Spoofing | A shopper acts as another shopper to read memory | The app, not the model, sets the actor id on every memory call; the model cannot choose it | The demo has no real sign-in; the shopper is picked in the UI | `app.py` (memory calls) |
| 3 | Tampering | Prompt injection in product text or the user prompt makes the agent misuse tools | Tools are read-only (search, inventory lookup); the agent has no write tools and no code execution; the search Lambda requires a query, caps `size` at 10 and coerces price bounds to numbers | A recommendation can still be skewed by hostile catalog text (public sample data that we load). No Bedrock Guardrail is attached to the demo agent; add one before any wider use. Recalled memory is passed as delimited data with a preamble, which lowers the risk but is not a control | `search_lambda.py`; `main.py`; `docs/limitations.md` |
| 4 | Tampering | Memory poisoning: a crafted message stored as a "fact" | Facts are written per shopper only, so the effect stays inside one shopper's actor; reset script clears demo shoppers | A shopper can poison their own memory | `osmemory.py` (`check_actor`) |
| 5 | Repudiation | No record of who ran what | AgentCore runtime logs and X-Ray traces, Lambda logs, CloudTrail | Logs are not centralised or alarmed. Log groups keep 90 days; the Lambda is limited to 5 concurrent executions | `agentcore.yaml:173,376-383` |
| 6 | Information disclosure | The collection is read from the internet | The collection's network policy allows only the VPC endpoint, and reading also needs an entry in the data access policy, which lists named roles | Roles in the same account with broad IAM could still read it | `collection.yaml`; `agentcore.yaml` (`AgentsDataAccessPolicy`) |
| 7 | Information disclosure | Secrets in the repository | `.gitleaks.toml` and the GitHub Actions workflow scan the full history; secrets live in Secrets Manager; `.env` and ids files are git-ignored | None known | `.github/workflows/ci.yml:29-34` |
| 8 | Information disclosure | Memory of one shopper returned to another | Every search covers exactly one actor, enforced by OpenSearch Memory; tested with Alice and Bob | Relies on the app passing the right actor | `osmemory.py`; `tests/unit/test_osmemory.py` |
| 9 | Denial of service | Model or search cost runaway | Search OCU capped (max 4); runtime session timeouts; Haiku used for agent turns; the search Lambda is limited to 5 concurrent executions | No per-user rate limit | `collection.yaml`; `agentcore.yaml:173` |
| 10 | Elevation of privilege | Runtime or Lambda role used for more than intended | Roles are scoped to the named collection, memory, runtime, secret and model resources | `Resource: "*"` remains only on X-Ray trace writes (runtime role) and `bedrock:Rerank` (connector roles), which have no resource type, and on `cloudwatch:PutMetricData`, which is limited by namespace (`bedrock-agentcore`). Workload access tokens are scoped to this runtime's workload identity. Model access is by family (`claude-haiku-4-5-*`, `claude-sonnet-4-5-*`) in any Region, which the cross-Region inference profiles need | `agentcore.yaml:397-406`; `tests/unit/test_agentcore_iam.py` |
| 11 | Elevation of privilege | Public use of the EC2 host or its Streamlit port | Streamlit binds to 127.0.0.1 and is reached only through SSM; the environment file is fetched into tmpfs at start and never stored on disk; the service runs as a non-root user | Anyone with SSM access to the instance can reach it; the instance's security group is outside this repository (see Assumptions) | `install_app.sh:29,74-86` |
| 12 | Tampering | A compromised or changed dependency is packaged into the runtime | Runtime dependencies are pinned with `==` in `infra/serverless/agentcore/requirements.txt` and installed as wheels only (`--only-binary=:all:`); a unit test fails if any entry is unpinned; `pip-audit` is run over the resolved set before a release | Transitive dependencies are pinned but not hash pinned; `pip-audit` runs in CI on every pull request and weekly against the pinned versions, but a package compromised before an advisory exists is not caught | `deploy_agentcore.py:71,121-123`; `test_deploy_agentcore_bucket.py` |
| 13 | Tampering | The Lambda or runtime package is uploaded to, or deployed from, a bucket the deployer does not own | `ExpectedBucketOwner` on every S3 call; the deployer refuses a bucket that another account owns; Block Public Access, default encryption and a TLS-only bucket policy are re-applied on every run | Anyone in the account with write access to the bucket can replace a package before deploy | `deploy_agentcore.py:78-99,113`; `test_deploy_agentcore_bucket.py` |
| 14 | Elevation of privilege | The app install path is abused to run commands as root on the host | Install runs through SSM `send_command` from the operator's credentials; the tarball comes from a single-use bucket with a random suffix through a 15-minute presigned URL and is deleted afterwards; the service runs as a non-root user with `NoNewPrivileges` | Anyone with `ssm:SendCommand` on the instance has root on it | `scripts/deploy_app_to_ec2.py:122-147`; `install_app.sh:73-86` |
| 15 | Spoofing | A caller reuses another shopper's runtime session id and reads that conversation | Session ids are random UUIDs the app generates; compute is isolated per runtime session; only the app role (and account administrators) can invoke the runtime | The runtime now takes the session id from the runtime context first and uses the payload value only when there is no context (a local run), so a caller cannot name another session in the payload (`main.py:156`); the id is still not bound to the shopper, so anyone who holds both a session id and invoke rights can continue that session | `main.py:156`; `agentcore.py` (`new_session_id`) |

## Out of scope and accepted

- Production hardening (WAF, private DNS, KMS customer keys, multi-account split, user authentication). See
  [limitations.md](limitations.md).
- Availability targets. This is a demo.

## Deployment guidance

The templates are samples. Deploy them only in a non-production account, review the IAM and network settings against
your own requirements, and do not load customer or regulated data.
